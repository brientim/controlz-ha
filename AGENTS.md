# AGENTS.md

ControlZ-style Rooms and Tiles for Home Assistant (Lovelace custom cards + `custom:controlz-rooms` dashboard strategy). Plain `HTMLElement` + shadow DOM, bundled with esbuild into `dist/controlz-ha.js`. No Lit and no Home Assistant frontend imports.

- `npm test`: unit tests for `src/model.js` (pure: area resolution, entity → tile kind, room badges, security view). Keep logic there, not in elements.
- `npm run build` then `npm run serve`, then open `http://127.0.0.1:8765/dev/harness.html` to check visually against the mock `hass` (`dev/fixture.js`; `dev/mock-hass.js` also fakes the automation config API, user data and entity registry updates per browser session, `?fresh=1` resets). `?open=<sheet>` opens a sheet, `?admin=0` is a non-admin user, `window.__errors` collects uncaught errors. Use headless Chrome for full-width screenshots (`dev/screenshots/`); it will not lay out narrower than 500 px, so check phones with device emulation.
- Deploy to the lab install: `python3 scripts/deploy.py` (see README for env vars). Never commit tokens, LAN addresses or screenshots of a live Home Assistant — this repo is public.
- Store packaging: since Home Assistant 2026.11 HACS is built in as the **Marketplace** (Settings → Marketplace); same catalog, same `hacs.json`, same `hacs/action`, category `plugin`. Marketplace resources live at `/local/community/controlz-ha/` (old `/hacsfiles/` still works) — `scripts/deploy.py` treats both as a store install. Packaging: `hacs.json` + GitHub release asset `controlz-ha.js`. Release with `./scripts/release.sh` after bumping `package.json` (`npm version patch --no-git-tag-version`). `.github/workflows/validate.yml` runs `hacs/action` (category `plugin`) plus tests and build.
- Design source of truth is ControlZ: `~/Developer/ControlZ/Targets/ControlZ/HTML/_preview_*_tiles.html` (tile size contract) and `~/Developer/ControlZ/docs/guides/ROOM_TILE_AND_SIDEBAR_BADGES.md` (badge rules). Keep them aligned when either side changes.
- Tile heights are fixed per size (Large 200 / Thin 100 / Compact 150). Never let a tile grow; move controls into the room sheet instead. Verify with `dev/harness.html?fit=1` (headless Chrome `--dump-dom`) — it must report zero problems.
- Tile scale (`tile_scale`, View menu 100/80/60%) zooms the page content below the header via CSS `zoom` with a measured px width (`--cz-inner`) — never percentage widths, which browsers resolve differently under zoom. Check `?fit=1&scale=0.6` (both navs).
- Per-device View menu choices live in `src/prefs.js` (localStorage `controlz-ha.prefs`) and override `tile_size` / `room_nav` / `tile_scale`; the same store keeps `home_filter` (All Rooms All / On / Off) and `start_page` (consumed once per page load via `takeStartPage()`). Elements re-render on `controlz-ha-prefs`. Run the fit check for both layouts: `?fit=1` and `?fit=1&nav=sidebar`.
- Hiding and order: `src/hidden.js` saves `hide_areas` / `hide_entities` / `areas_order` / `entities_order` (per area id, `__none` for automations without a room) into the ControlZ dashboard's strategy config via `lovelace/config/save` (admins only) and broadcasts `controlz-ha-hidden`; read them through `areasOrder(config)` / `entitiesOrder(config, area)` and apply with `orderItems()` before `groupBySection()`. Pages reorder through `CzPage.moveTile(id, { delta | beforeId }, group)`: tiles move only within their `data-wrap-group` (a section, the rooms, an automation room), and `reorderSubset()` keeps the rest of the room in place. Favorites order is the user's own (`setFavoritesOrder()`), open to non-admins. Edit mode is `controlz-ha-edit` and is open to every user: ♥ for everyone, hide and reorder (arrows, drag on All Rooms) for admins only. Hidden devices are excluded from room summaries via `visibleItems()`.
- Favorites: `src/favorites.js` stores `{ areas, entities }` per Home Assistant user with `frontend/get_user_data` / `frontend/set_user_data` (key `controlz-ha-favorites`, falls back to localStorage) and broadcasts `controlz-ha-favorites`. Sheets get a heart via `sheetFrame({ favorite: this.favoriteOn })` and the owner's `favoriteTarget()`. Which favorites get tiles is `favoriteItems()` / `favoriteAreas()` in `src/model.js`.
- Automations are their own tile kind (not scenes). Run always calls `automation.trigger` with `skip_condition: false` after a confirm; the skip-conditions run is a separate, confirmed action. Config read / save / delete use Home Assistant's admin-only API (`hass.callApi` on `config/automation/config/<id>`, `src/automation-editor.js`). The simple editor only opens when `simpleDraft()` (`src/automation-model.js`, pure, tested) can represent the whole config; anything else goes to Home Assistant's editor — never rewrite a richer automation in the simple form.
- Sheets with form fields: `CzSheet.refresh()` skips re-rendering while a text field / select is focused (Home Assistant pushes `hass` constantly); call `refresh(true)` for structural changes and update typed values without re-rendering.
- Security banner logic is `securityReport()` / `bannerSeverity()` in `src/model.js` (mirrors ControlZ `SecurityStateCalculator`: red doors/locks/hazards, amber windows/jammed, then motion).
- Every slider goes through `rangeRow()` in `src/controls.js`. Brightness (lightbulb icon, amber/white fill), covering position (blinds icon, blue fill) and fan speed (fan icon, teal fill) must never look alike — they sit together on mixed room tiles. Fans are teal when on and thermostats orange / blue while heating / cooling; only lights use the amber "on" tile.
- `src/room-icons.js` ports ControlZ `Targets/ControlZ/DeviceModels/RoomIconRegistry.swift` (SF entries, same order and suggestions). Keep it aligned when the Swift registry changes; import only named `@mdi/js` exports so esbuild tree-shakes the rest.
- Elements diff a JSON view model before re-rendering (`CzElement.requestRender`); Home Assistant pushes `hass` on every state change, so never re-render unconditionally.
